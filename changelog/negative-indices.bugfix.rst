Fix slicing `~ndcube.NDCube`, `~ndcube.NDCubeSequence` (including `~ndcube.NDCubeSequence.index_as_cube`), `~ndcube.NDCollection` and `~ndcube.NDMeta` with negative or out-of-range indices. ``cube[-1]`` and ``cube[-2:]`` now give the same world coordinates as the equivalent positive indices, and slices such as ``cube[-2:]`` or ``cube[1:10]`` no longer raise an error when the cube has axis-aware metadata. A slice that fails, such as ``cube[::2]``, no longer empties the original cube's ``meta``. Slicing an `~ndcube.NDCube` so that an axis would have length 0, e.g. ``cube[2:2]`` or ``cube[-1:1]``, now raises an `IndexError`.
